# Artlogos GA4 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development or superpowers:executing-plans to implement this plan task-by-task.

**Goal:** Collect useful GA4 events for Artlogos using `G-MK7GF137Y6` automatically, then publish and verify.

**Architecture:** A small client analytics module loads gtag once, sends an explicit document view, tracks current artwork context, and drops no-consent gating per the user's explicit override. React integration records artwork views and contact clicks; an independent localized notice explains collection without interrupting visitors.

**Tech Stack:** Existing React, TypeScript, Vite, node:test, Nginx and existing CI/deployment.

**Spec:** `docs/superpowers/specs/2026-11-06-ga4-design.md`

## Global Constraints

- Measurement ID is `G-MK7GF137Y6`.
- Automatic collection; no banner or consent question; never fabricate consent.
- Disable advertising personalization and Google signals. No PII in custom parameters.
- Only initialize in a browser on production hostname; provide explicit injectable environments for tests, not production test switches.
- No dependencies required; prerender must remain safe and unchanged in purpose.
- Preserve all seven languages and both themes.
- No unrelated file changes, no additional external messages.

## Review Focus

- StrictMode and repeated startup must not duplicate events/scripts.
- Reopening the same artwork should record a fresh view; moving to the next should record once.
- Initial root redirect must not create a phantom pageview.
- Query updates must preserve UTM/click IDs before analytics loads.
- Ad blockers or missing storage must never break portfolio navigation.
