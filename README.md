# Artlogos

Персональная страница художника на React, TypeScript и Vite.

```sh
npm install
npm run dev
```

`npm run build` проверяет TypeScript, собирает сайт в `dist/`, предварительно рендерит React в HTML и проверяет SEO-артефакты. `npm run preview` открывает собранную версию.

## Языки

Доступны английский (`/en/`), русский (`/ru/`), французский (`/fr/`), немецкий (`/de/`), итальянский (`/it/`), испанский (`/es/`) и японский (`/ja/`). Переведены интерфейс, тексты сайта, категории и теги, названия и описания картин, подписи и alt фотографий.

При входе через `/` или `/index.html` браузер выбирает язык и переходит на соответствующий адрес: сначала учитывается сохранённый выбор `localStorage["artlogos-language"]`, затем первый поддерживаемый язык из `navigator.languages` (или `navigator.language`, если список недоступен), затем английский. Региональный вариант сводится к базовому языку: например, `fr-CA` → `fr`. Язык системы учитывается через настройки языка браузера. Без JavaScript эти входные адреса показывают английский HTML.

Явный префикс в адресе всегда важнее сохранённого выбора и языка браузера: `/de/` и `/de/works/azure/` остаются немецкими. Переключатель языка в шапке содержит обычные ссылки, сохраняет ручной выбор и открывает ту же картину или состояние каталога на другом языке.

## Docker и CI

GitHub Actions (`.github/workflows/docker.yml`) собирает проект внутри Docker и проверяет запущенный контейнер: HTML всех картин, описания и фотографии без JavaScript, текстовые каталоги, JS/CSS, `/healthz`, кеширование, маршруты и 404 для отсутствующих файлов. Pull request запускает проверку без публикации. Push в `main`, теги `v*` и ручной запуск workflow на `main` / теге `v*` дополнительно публикуют образ для `linux/amd64` и `linux/arm64` в GHCR.

Образ: `ghcr.io/cattingcat/artlogos.space`. Теги: `latest` для `main`, `sha-<полный SHA коммита>` и имя release-тега. В summary успешного CI есть полный `image@sha256:...`; для ручного деплоя в кластер лучше закреплять этот digest. Образ nginx работает без root на порту **8080**, проверка готовности — **GET /healthz**. Автоматического деплоя в кластер нет.

```sh
docker pull ghcr.io/cattingcat/artlogos.space:latest
docker run --rm -p 8080:8080 ghcr.io/cattingcat/artlogos.space:latest
```

Локальная сборка и проверка:

```sh
docker build -t artlogos:local .
docker run --rm --name artlogos-local -p 8080:8080 artlogos:local
# В другом терминале:
python3 scripts/smoke-test.py http://127.0.0.1:8080
```

Публикация использует встроенный `GITHUB_TOKEN`, отдельные токены в репозитории не нужны. Для скачивания без авторизации GHCR package должен иметь visibility **Public** (она настраивается отдельно от публичности репозитория). Базовые образы Docker и Actions закреплены по digest/SHA; обновлять их нужно явно. `dist/` и `node_modules/` не коммитятся и не отправляются в Docker build context.

## Коллекция и фотографии

Коллекция импортирована из пользовательского архива `Портфолио.zip` и дополнена новыми работами: **38 картин, 58 фотографий работ и 2 фотографии для разделов About / Studio**. У двенадцати картин есть несколько снимков. Уменьшенный дубль интерьера церкви исключён в пользу оригинала большего разрешения.

- `src/content/portfolio.json` — идентификаторы картин, исходные названия и описания, категории, теги, публикации и массив `images`. Первая фотография — обложка карточки; порядок остальных задаёт порядок галереи.
- `src/content/artworks.ts` — типы данных и список категорий.
- `public/portfolio/<id>/` — оптимизированные WebP и отдельные превью до 720 px. Импортированные кадры уменьшены до 2200 px по длинной стороне; новые версии `In the museum`, `Saint Sophia Cathedral`, `Portrait in Sunlight`, `At 5 a.m`, обложки `Voice` и `An Evening in St Petersburg` и дополнительные крупные планы `About Zero`, `Sailboat` и `Azure` сохраняют полное разрешение исходников. Кадры сохраняют исходные пропорции; оригиналы не изменены. Заменённые изображения получают новые имена с хешем, чтобы обходить старый кеш.
- `scripts/portfolio-sources.json` — соответствие каждой работы исходным файлам, источники названий и описаний, редакционные фотографии и исключённый дубль. Поле `titleSource: descriptive` отмечает оставшиеся рабочие названия по видимому сюжету.
- `src/content/site.ts` — общая идентичность художницы, адрес сайта, изображения About / Studio, контакты `email`, `telegram`, `discord` и 12 ссылок на профили в `socialLinks`.
- `src/i18n/locales/{en,ru,fr,de,it,es,ja}.json` — отображаемые тексты каждого языка: интерфейс, SEO, разделы сайта, категории, теги и записи картин. `src/i18n/catalog.ts` объединяет переводы с общими данными и файлами изображений.
- `src/content/socialIcons.ts` — локальные SVG-иконки Simple Icons (CC0); для Cara и Saatchi Art используются собственные художественные символы.

Названия и описания сверены с публикациями художницы на DeviantArt. Дополнительно проверен Saatchi Art; при совпадении приоритет у текста DeviantArt. Повторяющиеся рекламные блоки, ссылки на соцсети и видео из описаний убраны. Ссылки на исходные публикации доступны в открытой картине. Неподтверждённые сведения не добавляются; техника и размеры сохраняются только там, где они прямо указаны в авторском тексте. Теги описывают видимые сюжеты и учитывают авторский контекст: воду, деревья, архитектуру, время суток и времена года. Категории: `Landscapes`, `Cityscapes`, `Figures`, `Portraits`, `Interiors`.

Проверка 8 октября 2026: найдены **34 авторских названия и 32 описания**. У `Closed for the season` и `W a v e s` описание в источнике пустое. `Portrait in Sunlight` и `Domes through Autumn Leaves` не сопоставлены с публикациями и пока сохраняют рабочие названия.

Для новой картины добавьте объект с полями `id`, `title`, `category`, `tags` и `images`. Необязательное поле `description` содержит простой текст (пустая строка разделяет абзацы), `sources` — массив `{ label, url }`. Каждый снимок содержит `src`, `thumbnail`, `alt`, `label`, `width`, `height`. Для новой картины обязательно добавьте запись с тем же `id` во все семь файлов `src/i18n/locales/*.json`: переведённые `title`, существующее `description` и `images` с `label`/`alt` для каждого снимка. Ключи, наличие описания и порядок фотографий должны совпадать во всех языках; плейсхолдеры интерфейса вроде `{count}` сохраняются. Для новой категории или тега также нужны переводы во всех словарях. Чтобы поменять обложку, переставьте нужный снимок на первое место вместе с соответствующими переводами фотографий. Сохраняйте `id` существующих картин, чтобы не ломать прямые ссылки.

## Просмотр

Сетка содержит 3 колонки от 1200 px, 2 колонки на ширине 660–1199 px и 1 колонку до 659 px. Картины целиком вписаны в паспарту с полем 12 px; подписи и счётчики фотографий вынесены за изображение.

Светлая тема «Тёплый минерал» и тёмная «Графитовый архив» заданы семантическими переменными в `src/theme.css`. Кнопка в шапке доступна с клавиатуры; ручной выбор хранится в `localStorage["artlogos-theme"]` и имеет приоритет над `prefers-color-scheme`. Пока ручного выбора нет, сайт следует изменениям системной темы. Синхронный скрипт в `index.html` применяет тему до отрисовки; обе темы работают на всех языковых страницах. Переходы цветов отключаются при `prefers-reduced-motion`. Цвета картин не фильтруются; инверсия применяется только к чёрному логотипу в тёмной теме.

Категория, выбранные теги и сортировка хранятся в параметрах URL и сохраняются при смене языка. Фильтры по тегам выбирают работы со **всеми** отмеченными тегами. Сортировка — кураторский порядок или переведённое название с учётом текущего языка.

Нажатие на карточку открывает одну картину: крупный снимок, миниатюры и счётчик фотографий. Стрелки клавиатуры и свайп переключают её снимки. Отдельные кнопки Previous / Next artwork переключают картины. Escape и нажатие на фон закрывают окно; фокус возвращается в каталог. Прямые ссылки вида `?category=figures&work=forest-figure` и история браузера поддерживаются.

Постоянные адреса картин — `/<язык>/works/<id>/`, например `/ru/works/azure/`. По ним доступна отдельная страница с переведённым описанием, всеми ракурсами и ссылками на исходные публикации. Открытие карточки в новой вкладке или без JavaScript ведёт на эту страницу. Старые `/works/<id>/` сохранены как английские версии с canonical на `/en/works/<id>/`.

Все изображения демонстрационных сторонних работ удалены. Визуальная композиция сайта основана на ранее выбранных референсах; содержание теперь из предоставленного портфолио. Шрифты подключаются с Google Fonts; без сети используются Georgia и Arial.

## Поиск по имени художницы

Все языковые версии сохраняют латинские имена **Alina Logos** и **Alina Pliushcheva** в видимом тексте, title, description и JSON-LD, чтобы связывать локализованные страницы с одной художницей. `sameAs` связывает автора с указанными профилями. При сборке `scripts/prerender.mjs` сохраняет React-каталог, описания и контакты в HTML для каждого языка; JavaScript добавляет фильтры и галерею через гидратацию. Отдельный Node-сервер в продакшене не нужен.

Сборка создаёт **273 локализованных HTML-страниц**: главную и 38 картин на каждом из семи языков. Каждая имеет собственный canonical на адрес с языковым префиксом, корректный `html lang`, переведённые title, description, Open Graph / Twitter и JSON-LD. На страницах картин `VisualArtwork` содержит переведённые название, описание, теги и подписи изображений с общей идентичностью художницы. Полные описания и все фотографии доступны до выполнения JavaScript. Параметры категорий, фильтров, сортировки и открытых диалогов остаются состояниями главной, без отдельных canonical.

Все страницы связаны взаимными `hreflang` для семи языков. `x-default` у главных ведёт на `https://artlogos.space/`, у картин — на их английскую страницу `/en/works/<id>/`. Дополнительно сохранены **39 английских HTML-страниц без языкового префикса**: `/` и `/works/<id>/`; их canonical указывают на соответствующие `/en/`-адреса.

Сборка генерирует `dist/sitemap.xml` с 273 каноническими языковыми адресами, альтернативами `hreflang` и полноразмерными изображениями; старые английские алиасы в sitemap не включаются. Для каждого языка создаются `/<язык>/llms.txt` со ссылками и `/<язык>/llms-full.txt` с переведёнными описаниями, фотографиями и контактами. `/llms.txt` и `/llms-full.txt` сохраняются как копии английских каталогов. Эти текстовые версии помогают агентам читать каталог, но не гарантируют индексацию или позиции. Сгенерированные файлы в `dist/` вручную не редактируются.

`robots.txt` разрешает обход. Nginx перенаправляет `www` на основной домен и возвращает 404 для неизвестных путей, включая несуществующие картины. HTML страниц и текстовые каталоги требуют перепроверки кеша при каждом запросе. `npm run check:seo` проверяет уже собранный `dist/`: полноту семи словарей и плейсхолдеров, все языковые страницы и legacy-копии, переводы в HTML/метаданных/JSON-LD, canonical и взаимные `hreflang`, ссылки, изображения, sitemap и текстовые каталоги. Эта проверка также входит в обычную сборку и Docker CI.

После публикации:

1. Проверить HTTP 200 для главной, `robots.txt`, `sitemap.xml` и изображений; проверить редирект с `www`.
2. Подтвердить домен в Google Search Console, отправить `https://artlogos.space/sitemap.xml`, проверить языковые URL, например `/ru/` и `/en/`, и запросить индексацию.
3. Добавить ссылку `https://artlogos.space/` в профили художницы и использовать оба имени последовательно. Внешние профили этим проектом не редактируются.

Техническая готовность не гарантирует позиции в выдаче. Изменения в этом репозитории публикуют образ, но не обновляют приложение в кластере автоматически.
